Getting the other accounts' numbers

This app runs as one account and can't read another account's login token. Windows refused access to profile 2's .claude folder, and profile 3 has no token file in its profile. So each account has to report its own numbers.

  • Hook in each account (proposed). A small hook script is added to each account's Claude settings. When Claude finishes a turn in that account, the script runs as that account, reads that account's own token, fetches its usage, and writes it to a shared folder the app watches. Usage only goes up while that account is in use, and the app can work out resets itself from resets_at, so updating on each turn is enough.
  • Fetch as the account (fallback). The app already starts VS Code as another account with the password saved in Credential Manager. It could start a hidden fetch the same way. That only works for accounts whose password is saved, so I'd keep it as a fallback.

Showing an expired login without hovering

New

Today an expired login just greys the rings, which can look like 0% usage. Each option below makes "can't read this account" look different from any real reading. Left pair: your account, read fine (10% / 46%). Right pair: profile 2, whose login expired at 01:13 (its last reading was 5% / 1%). Transparent background and no badge, as in your config. Each strip is shown at 2× and then at real size.

A · Last reading in grey, breathing

The last numbers stay, in grey, and the pair slowly fades in and out. It's clear the numbers are old, and you still see roughly where the account was.

B · Dashed amber outline, breathing

No arcs at all, just a dashed amber outline that fades in and out. A broken ring can't be mistaken for a number.

C · Amber arc chasing round

No arcs, and a short amber arc runs round the outer ring, like the AI indicator's Working spinner. It reads as "waiting", which matches what's happening: the app is waiting for Claude Code to renew the login.

D · Amber "!" instead of rings

The rings are replaced by a single grey circle with a pulsing amber "!". It's the loudest option and doesn't depend on reading the rings at all.

My pick: B. It never shows a number that could be misread, it's calm enough to sit on screen for hours (profile 2 can stay expired all day), and it keeps the ring shape so the hub's layout doesn't jump. Animation would follow the AI indicator's: a repaint timer that runs only while some pair is in that state.

How it changes as you use it

Colors follow the API's own severity for each limit. The meter goes grey when the data is old (for example, the login token expired and no Claude Code session has renewed it).

5h38%2h01m

Normal. Under pace, so you have room.

5h74%2h45m

Warning. Well ahead of pace.

5h96%0h58m

Critical. Optionally a tray balloon the first time it crosses 90%.

5h38%?

Stale. Last good value, greyed, with the age in the tooltip.

Where the numbers come from

This is the same data Claude Code's /usage screen shows. I called it once from this machine and it answered:

GET https://api.anthropic.com/api/oauth/usage
Authorization: Bearer <claudeAiOauth.accessToken from ~/.claude/.credentials.json>
anthropic-beta: oauth-2025-04-20

"five_hour":  { "utilization": 2.0,  "resets_at": "2026-10-20T21:19:59Z" }
"seven_day":  { "utilization": 38.0, "resets_at": "2026-10-25T06:59:59Z" }
"limits": [ { "kind": "session",    "percent": 2,  "severity": "normal" },
            { "kind": "weekly_all", "percent": 38, "severity": "normal" } ]
  • Undocumented endpoint. It isn't a public API, so the shape can change. The app should parse it defensively and show "stale" rather than wrong numbers.
  • Read the token, never refresh it. Claude Code renews the token itself. If this app refreshed it, it could rotate the refresh token and log Claude Code out. When the token has expired, the meter shows stale until Claude Code renews it.
  • Polling. Every 3 minutes over WinHTTP, plus once on the Claude hooks this app already installs (Stop and similar), so the meter moves right after a turn ends.

My recommendation

Build C, the twin rings, as you chose, with one ring pair per account and the account's badge in front (layout 1). Add the highlight for the focused window's account (layout 3), but never dim an account that is in warning or critical. Hovering any pair shows exact percentages and reset times. Put it all behind a usage_meter_enabled setting in config.ini.
